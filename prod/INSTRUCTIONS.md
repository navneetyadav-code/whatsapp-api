# WhatsApp API - Production Deployment Instructions

This guide provides full instructions for hosting the **WhatsApp API Gateway** 100% free with 24/7 uptime without needing a local machine or a credit card.

---

## Architecture Overview

- **Web Server & Backend**: PHP 8.2 (Apache) running the web dashboard and REST API.
- **WhatsApp Worker**: Node.js 20 running Baileys WhatsApp Web socket engine on internal port `3107`.
- **Process Manager**: Supervisord inside a Docker container orchestrating both Apache & Node.js simultaneously.
- **Database**: TiDB Cloud Serverless (MySQL-compatible, 5 GB storage, always free tier).
- **Hosting Platform**: Render Free Web Service ($0/month, Docker runtime).
- **Keep-Alive**: UptimeRobot (Free HTTP ping every 5 minutes to prevent Render free instance from sleeping).

---

## Step 1: Database Setup on TiDB Cloud

1. Log in to [TiDB Cloud](https://tidbcloud.com/).
2. Open your cluster SQL Editor (e.g. `assistgroup`).
3. Open `prod/schema_production.sql`.
4. Copy the entire contents of `schema_production.sql`.
5. Paste it into the TiDB Cloud SQL Editor.
6. Select all text (`Ctrl + A`) and click **Run** (or `Ctrl + Enter`).
7. Verify all statements execute with green checkmarks.
8. On the left sidebar under **Schemas**, refresh and expand `test`. You should see 14 tables:
   - `users`
   - `api_keys`
   - `whatsapp_sessions`
   - `message_queue`
   - `templates`
   - `campaigns`
   - `campaign_recipients`
   - `scheduled_messages`
   - `quick_replies`
   - `chat_history`
   - `chat_conversations`
   - `chat_labels`
   - `chat_conversation_labels`
   - `rate_limits`

## Step 2: Deploy Web Service on Render

1. Log in to [Render](https://dashboard.render.com/).
2. Click **New +** at the top right and select **Web Service**.
3. Choose **Build and deploy from a Git repository**.
4. Select the repository: `navneetyadav-code/whatsapp-api`.
5. Configure the service:
   - **Name**: `whatsapp-api`
   - **Region**: `Singapore` (Recommended for low latency with TiDB AWS ap-southeast-1) or `Oregon`
   - **Branch**: `main`
   - **Runtime / Environment**: `Docker` (Auto-detected from `Dockerfile`)
   - **Instance Type**: `Free ($0/month)`
6. Scroll down to **Environment Variables** and add the following keys:

| Environment Variable | Recommended Value | Notes |
| :--- | :--- | :--- |
| `APP_ENV` | `production` | Enables production mode |
| `DB_HOST` | `gateway01.ap-southeast-1.prod.aws.tidbcloud.com` | TiDB Cloud Gateway Host |
| `DB_PORT` | `4000` | TiDB Port |
| `DB_USER` | `3QGgvLi97sMDpPA.root` | TiDB Username |
| `DB_PASSWORD` | `<YOUR_TIDB_PASSWORD>` | Password generated by TiDB |
| `DB_NAME` | `test` | Target Database name |
| `DB_SSL` | `true` | Required for TiDB Cloud |
| `WORKER_URL` | `http://127.0.0.1:3107` | Internal Docker worker loopback |
| `WORKER_TOKEN` | `a7c8e547f63d410db901e149c71c6ae2` | Secret shared between PHP & Worker |
| `DEFAULT_COUNTRY_CODE` | `91` | India (+91) |

7. Click **Create Web Service**.
8. Render will build the Docker image and start the container. When the deployment finishes, status will turn **Live** with a public URL like `https://whatsapp-api-xxxx.onrender.com`.

## Step 3: Keep-Alive via UptimeRobot (Prevent Render Sleeping)

Because Render free web services spin down after 15 minutes of inactivity, set up a free Uptime ping:

1. Sign up / Log in to [UptimeRobot](https://uptimerobot.com/) (100% free, no credit card).
2. Click **Add New Monitor**.
3. **Monitor Type**: `HTTP(s)`
4. **Friendly Name**: `WhatsApp API Keep-Alive`
5. **URL (or IP)**: `https://<YOUR-RENDER-APP>.onrender.com/api/health.php`
6. **Monitoring Interval**: `5 minutes`
7. Click **Create Monitor**.

Now your WhatsApp API will run 24/7 without ever going to sleep!

## Step 4: Connect WhatsApp Device

1. Open your live app: `https://<YOUR-RENDER-APP>.onrender.com/public/index.php?page=device`
2. Log in using your credentials.
3. Click **Connect**.
4. Scan the QR code using your WhatsApp app (**Linked Devices** > **Link a device**).
5. Once connected, state will switch to **Connected** and you can begin sending messages via API immediately.
