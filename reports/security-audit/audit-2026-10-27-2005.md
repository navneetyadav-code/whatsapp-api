## Identified Vulnerabilities & Applied Remediation

### 1. Unchecked Request Body Null-Dereference on Direct Send Handler
- **Classification:** CWE-754 (Improper Check for Unusual or Exceptional Conditions) / CWE-20 (Improper Input Validation) / OWASP A04:2021 (Insecure Design)
- **Severity:** Medium (CVSS 5.3)
- **File Affected:** `worker/server.mjs` (Lines 2140–2142)
- **Vulnerability Mechanism:**
  In `worker/server.mjs`, the route `app.post('/sessions/:userId/send')` safely guarded `req.body?.to` using optional chaining, but dereferenced `req.body.message` on the subsequent line without optional chaining. When clients transmitted an empty body, malformed non-JSON payload, or omitted the `Content-Type: application/json` header, `req.body` remained `undefined`. Evaluating `String(req.body.message || '').trim()` triggered an uncaught `TypeError: Cannot read properties of undefined (reading 'message')` inside an Express async route handler, resulting in an unhandled promise rejection and crashing or hanging the incoming request socket rather than gracefully returning an HTTP 422 validation response.
- **Remediation Applied:**
  Applied safe optional chaining on `req.body?.message` in `worker/server.mjs` line 2141 and guarded `req.body?.auto_sleep_enabled` on line 2082:
  ```javascript
  const recipient = normalizeRecipient(req.body?.to);
  const message = String(req.body?.message || '').trim();
  ```
  This guarantees that empty or malformed request payloads evaluate `message` to `""`, cleanly triggering the existing validation guard `if (!recipient.jid || !message)` to return an immediate HTTP 422 JSON error response without runtime exceptions.
- **Verification Status:**
  - Syntax checked with `node --check worker/server.mjs`
  - Automated test assertion added and verified in `tests/cli-sapi-and-access-control.test.php`
  - Node test suite passed with 77/77 tests: `node --test tests/*.mjs`
