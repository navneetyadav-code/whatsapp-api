## Identified Vulnerabilities & Applied Remediation

### 1. Direct Request and Missing SAPI Barrier on Database Migration Utility
- **Classification:** CWE-306 (Missing Authentication for Critical Function) / CWE-425 (Direct Request / 'Forced Browsing') / CWE-200 (Information Exposure) / OWASP A01:2021 (Broken Access Control)
- **File Affected:** `scripts/migrate.php` (Lines 1–10)
- **Severity:** High (CVSS 7.5)
- **Vulnerability Mechanism:**
  `scripts/migrate.php` executes critical database schema DDL migrations, creates tables, alters missing columns, and repairs schema indexes and constraints. While `scripts/create-initial-admin.php` and `setup.php` enforced strict CLI execution barriers (`PHP_SAPI !== 'cli'`), `scripts/migrate.php` lacked any SAPI validation. If invoked directly via HTTP under web server configurations where the repository root is accessible, the script would execute migration logic, output schema structure messages to `STDOUT` (`Database schema is ready: 13 application tables in ...`), disclose the database name and schema state to remote clients, and allow unauthenticated remote actors to trigger repeated DDL locks and schema execution overhead.
- **Remediation Applied:**
  Added an immediate CLI execution guard at the top of `scripts/migrate.php`:
  ```php
  if (PHP_SAPI !== 'cli') {
      http_response_code(404);
      exit;
  }
  ```
- **Verification Status:** Passed syntax verification with `php -l scripts/migrate.php`. Verified CLI execution and HTTP abort with `php tests/cli-sapi-and-access-control.test.php`.

### 2. Web Server Root Access Control Rule Gap for Scripts and Test Directories
- **Classification:** CWE-552 (Files or Directories Accessible to External Parties) / OWASP A05:2021 (Security Misconfiguration)
- **File Affected:** `.htaccess` (Line 10)
- **Severity:** Medium (CVSS 5.3)
- **Vulnerability Mechanism:**
  The repository root `.htaccess` contained a `RedirectMatch 404` rule configured only for `"^/whatsapp-api/(config|src|worker)(/|$)"`. This rule omitted internal utility directories (`scripts` and `tests`) and only matched requests with the `/whatsapp-api/` path prefix. In hosting environments where DocumentRoot is set to the project root, requests directly targeting `/scripts/...` or `/tests/...` were not blocked by this rule.
- **Remediation Applied:**
  Updated the regex pattern in root `.htaccess` to:
  ```apache
  RedirectMatch 404 "^/(whatsapp-api/)?(config|src|worker|scripts|tests)(/|$)"
  ```
  This ensures that direct requests targeting `config`, `src`, `worker`, `scripts`, or `tests` return HTTP 404 regardless of whether the URL includes the `/whatsapp-api/` prefix.
- **Verification Status:** Verified with `tests/cli-sapi-and-access-control.test.php` and `tests/setup-protection.test.php`.

### 3. Unchecked Request Body Null-Dereference in Worker Direct Send Handler
- **Classification:** CWE-754 (Improper Check for Unusual or Exceptional Conditions) / CWE-20 (Improper Input Validation) / OWASP A04:2021 (Insecure Design)
- **File Affected:** `worker/server.mjs` (Line 2140)
- **Severity:** Low / Medium (CVSS 4.3)
- **Vulnerability Mechanism:**
  In `worker/server.mjs`, `app.post('/sessions/:userId/send')` directly accessed `req.body.to` without optional chaining or validating that `req.body` is populated. When non-JSON payloads or empty request bodies with mismatched `Content-Type` headers reached this endpoint, accessing `req.body.to` caused an uncaught `TypeError: Cannot read properties of undefined (reading 'to')`. In Express async handlers, this resulted in an unhandled rejection, hanging the socket until client timeout.
- **Remediation Applied:**
  Applied safe optional chaining on the request body:
  ```javascript
  const recipient = normalizeRecipient(req.body?.to);
  const message = String(req.body?.message || '').trim();
  ```
  This allows the downstream parameter validation guard (`if (!recipient.jid || !message)`) to cleanly reject malformed requests with an immediate HTTP 422 JSON response without throwing runtime exceptions.
- **Verification Status:** Passed syntax verification with `node --check worker/server.mjs`. Verified with `tests/cli-sapi-and-access-control.test.php`.
